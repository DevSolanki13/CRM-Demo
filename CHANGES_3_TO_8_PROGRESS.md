# Changes 3–8: implementation status

Updated 2026-10-25. This records what is implemented in this checkout and what still needs work from [REMAINING_CHANGES.md](REMAINING_CHANGES.md). It does not mark the whole backlog complete.

## Implemented

- **3 — Reporting:** A deal now stores the stage where it was lost. The migration backfills only from executed approval records or explicit loss audit metadata; uncertain cases display Unknown. The sales-rep filter applies to won revenue, renewals, rebuy metrics, accounts, loss breakdowns, and the audit table. Forecast probabilities and monthly rep targets are configurable in Settings. Regression tests cover multiple reps, closed and recurring deals, accounts, loss origins, and targets.
- **4 — Customer records:** Added an inventory script, ownership and customer-link foreign keys and indexes, restrictive deletion with an audit entry, immutable activity history through the API, reset protection for nonempty workspaces, and audited contact/company merge endpoints. Contact and company merge controls are now available to managers and admins. The missing parent-deal ID was preserved in a reconciliation record before clearing that invalid pointer; a parent-deal foreign key now protects new data. Six historical task/activity links are archived for review, and database triggers reject new invalid links. Admins can repair the seven archived references in Settings, with the original ID and decision kept in the audit trail. Task-to-approval and approval-to-deal foreign keys now protect those links, and deletion triggers prevent customer records being removed while polymorphic task/note/activity history still points to them.
- **5 — Automation:** A separate worker (`npm run worker`) performs renewal checks. `npm run automation:once` and a bearer-protected `POST /api/internal/automation/run` endpoint support external schedulers. Renewal runs and follow-up events persist status, leases, retry times, errors, and deduplicated side effects in PostgreSQL. Settings shows failure status. Tests cover competing workers, expired leases, retries, and follow-up deduplication. The actual deployment still needs a worker or scheduler and `CRON_SECRET`.
- **6 — Product configuration:** Admins can configure manager review for every advance or focus it on deal value, discount, and missing checklist answers. Sales labels on Reports and Settings were simplified. Pipelines now have separate stages, stable codes, configurable qualification fields, stage transitions, board selection, and report filtering. Existing deals were migrated into the Sales pipeline without changing their stage IDs. The API and database reject cross-pipeline stage assignments. Supabase Storage attachment routes and Files panels were added for deals, leads, contacts, and companies, with record access checks, private-bucket enforcement, audited deletion, and retryable cleanup. Actual upload/download cannot be verified until Storage credentials and a private bucket are configured.
- **7 — Scale:** Added database-scoped, cursor-paginated collection endpoints. Legacy list reads now query only the requested collection, and write authorization checks only the referenced records and owners instead of loading the entire workspace. Rep state uses scoped queries; mutations refresh affected client collections. Reports use database aggregation and cursor-paginated audit history. Initial dashboard loading omits Contacts, Companies, Notes, and approval checks; those collections load when needed by their views. View-level code splitting removed the production chunk-size warning. Lint runs without warnings.
- **8 — Account setup and verification:** Individual sign-in and one-time account invitation/recovery links are mounted. Sign-in attempts are counted in PostgreSQL across app replicas. In development, the shared workspace remains available until an administrator password is provisioned; production returns a setup error until `npm run admin:create` has been run. All 17 migrations (the original five and twelve later migrations) are applied to the connected Supabase database. On 2026-10-25, all 77 tests, lint, Prisma generation, and the production build passed. The shared local browser rendered reports, historical-link repair, independent pipeline controls, and the Files panel without errors.
